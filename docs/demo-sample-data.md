# Demo reference: questions and sample documents

Use this file beside the app at http://127.0.0.1:8502. Copy the text inside
each code block into the named field; do not include the surrounding backticks.
The questions and document drafts start empty. The baseline KB still contains
the repository's demo documents. All sample content below is synthetic.

Keep the same browser tab open throughout the demo so the KB changes and pinned
answers remain in the same session. Answers are generated by the configured
model, so wording and retrieval scores can vary.

## 1. Restore the baseline

Open **Knowledge base → Reset & activity → Restore baseline corpus**.
This removes documents added during earlier runs and restores the default
1,800-character chunk limit. Earlier answers remain in history; generate a new
baseline answer for this run.

## 2. Ask a question before adding the missing details

Open **Live Q&A**. Set **Source scope** to **Legacy only**.

Paste into **Your question**:

```text
What are the exact AMI meter retry limits and backoff timings?
```

Click **Generate answer**, inspect **Cited evidence** or **Retrieved sources**,
then click **Pin baseline**.

What to explain: the baseline has **Retry handling** from
`MeterDataIntegration.md` and **Retry discussion** from an email thread. These
describe backoff and missing documentation, without the exact retry settings.
The answer should acknowledge that gap; do not present unsupported numbers as
established facts.

## 3. Publish the clarification

Click **Add document** or open **Knowledge base → Add document**.

**New document title**:

```text
AMI retry configuration — owner clarification
```

Set **New source version** to **Legacy** and **Source type** to **Document**.

Paste this entire block into **New source content**:

```markdown
# AMI meter retry configuration — owner clarification

Synthetic demo update | Integration Operations | 2026-09-29

## Confirmed retry settings
The AMI meter upload integration retries a failed upload up to 4 times.
The delays before those retries are 5 seconds, 10 seconds, 20 seconds, and
40 seconds. After the fourth unsuccessful retry, the upload is moved to
the dead-letter queue and an operations alert is raised.

## Scope and provenance
These values describe the legacy AMI meter upload integration in this
synthetic demonstration. This note supplements MeterDataIntegration.md,
which describes exponential backoff without specific values. The earlier
email about missing durable documentation predates this clarification.
These settings do not describe BLPTS license renewals or inspections.

## Recovery
An operator reviews the dead-letter queue, fixes the underlying failure,
and replays the upload. Preserve the original upload identifier to avoid
duplicate meter readings. Alert ownership rests with Integration Operations.
```

Show **Chunk preview**, then click **Publish to knowledge base**. Wait for the
confirmation directly below the button. Publishing adds the document and makes
its chunks searchable; typing alone does not change the KB.

## 4. Inspect chunk boundaries

Open **Chunk explorer**. In **Document to inspect**, select
**AMI retry configuration — owner clarification**.

At the default 1,800-character limit this document fits in one chunk. Set
**Maximum characters per chunk** to **400** to preview several passages.
The colors show where the source text is split. Click
**Apply chunk size & rebuild index** to apply this size to every KB document.
Leaving the slider as a preview does not change retrieval.

For the most direct before/after evidence comparison, return the size to
**1800** and rebuild before the next step. Use **400** if your presentation is
specifically demonstrating how chunk size changes the retrieved passages.
